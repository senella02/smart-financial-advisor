# Ownership and File Insertion Points

These are role responsibilities for independent feature work, not named assignments. The Lead coordinates shared changes; feature contributors can work in their owned paths once contracts are agreed. Keep feature behavior and acceptance in the [requirements](functional-requirements.md), not in this guide.

- **Frontend:** `apps/web/src/app/page.tsx` (Home indices and Daily Brief), `apps/web/src/app/stocks/[market]/[symbol]/page.tsx` (quote, daily summary, stock chat), and `apps/web/src/app/chat/page.tsx` (main chat and combined history). Shared navigation is `apps/web/src/app/layout.tsx`, Thai UI text is `apps/web/src/messages/th.ts`, and styles are `apps/web/src/app/globals.css`. Replace placeholders within the existing semantic sections; preserve demo labels while data is fixtures.
- **Backend:** `apps/web/src/server/research.ts` is the current UI/BFF composition point; `apps/web/src/server/adapters/fixture-market-data.ts` shows the `MarketDataPort` seam. Add validated Route Handlers in `apps/web/src/app/api/` only as needed. No separate service or job runtime is selected.
- **AI:** `GenerationRequestSchema`, `GeneratedTextSchema`, and `GenerationPort` in `packages/contracts/src/index.ts` define the shared grounding/generation seam. `apps/web/src/server/adapters/fixture-generation.ts` is the no-generation adapter. Grounding, citation checks, bilingual generation, and future shared publication services belong behind this server boundary; do not put model calls in page components.
- **Lead:** reviews/integrates `packages/contracts/src/index.ts`, `packages/contracts/src/fixtures.ts`, contract tests, root tooling, `.github/workflows/checks.yml`, and ADRs. Owns cross-role integration and resolves merge overlap, without making unanswered product decisions.

For a contract change, agree on the smallest schema/example update with affected roles first; identify its producers and consumers, then update schema, inferred type, fixtures, adapter, UI, tests, and docs together. Preserve requirement IDs and distinguish internal ports from real provider contracts. Keep shared publications separate from private conversation and future account state. The [contract guide](contracts-and-boundaries.md) explains these boundaries.

No person, feature allocation, database, hosting platform, model, or financial-data provider is assigned here. SFA-5 only supplies the shared foundation; full Daily Brief, stock summaries, chat, and persistence remain feature work.
