# Final architecture service options

Provider documentation checked on 21 November 2026.

Which options fit the account-based Smart Financial Advisor with the least change to Next.js on Vercel, Supabase PostgreSQL, Pinecone, and the Vercel AI SDK? The ranking favors existing integrations and low operating effort after checking requirements for private data, Thai and US coverage, and permitted use. Provider documentation establishes advertised features and plan limits. Rankings are judgments about project fit. Thai retrieval quality, symbol-level feed coverage, and operating costs still need measurement.

## Authentication and Discovery access

1. **Supabase Auth.** It has a Next.js App Router integration and keeps identity alongside the existing PostgreSQL database. Google sign-in gives users with a Google account a short path. Email one-time codes add a path for other users and require a production email sender. The app still checks account ownership on the server, and the publication worker uses a separate database role. [Next.js integration](https://supabase.com/docs/guides/auth/quickstarts/nextjs) · [Google sign-in](https://supabase.com/docs/guides/auth/social-login/auth-google) · [SMTP setup](https://supabase.com/docs/guides/auth/auth-smtp) · [Supabase pricing](https://supabase.com/pricing)
2. **Clerk.** Managed sign-in screens and a supported Supabase integration reduce identity UI work. Clerk introduces a second service and identity mapping. The integration still requires ownership policies on exposed data. [Supabase integration](https://clerk.com/docs/guides/development/integrations/databases/supabase) · [Clerk pricing](https://clerk.com/pricing)
3. **Better Auth.** It runs within Next.js and uses PostgreSQL. The project owns the deployment, maintenance, and session integration. It fits if control of the identity stack becomes more important than managed operations. [Next.js integration](https://better-auth.com/docs/integrations/next) · [PostgreSQL adapter](https://better-auth.com/docs/adapters/postgresql)

For Discovery, rank **signed-in only** first. It reuses the chat access rule and the account's confirmed plan and optional Investor Profile. A **guest preview with sign-in to screen** adds an entry point with less friction and needs an explicit rule for what survives sign-in. **Full guest screening** offers the widest access and adds guest plan ownership and abuse controls. [Access questions](../requirements-questions.md#q03-access-persistence-and-languages) · [Discovery requirements](../final/functional-requirements.md#fr-15-discovery-plan-and-user-confirmation)

## Model for private AI context

1. **Paid Gemini Developer API.** This keeps the chosen model family and AI SDK integration. Google states it does not use paid prompts and answers to improve its products and retains them for a limited period for safety, abuse prevention, and related disclosures. Approve the intended context, retention, and audience before using it for account data. The Developer API terms also restrict apps likely to be accessed by under-18s. [Gemini terms](https://aistudio.google.com/docs/terms) · [Gemini pricing](https://aistudio.google.com/docs/pricing)
2. **Gemini on Google Cloud Vertex AI.** It stays within the Gemini family and has an AI SDK provider. It adds Cloud billing, service identity, and regional model configuration. It is a stronger candidate when private processing needs Cloud controls that the Developer API lacks. Check controls and retention for the exact features used. [AI SDK integration](https://ai-sdk.dev/providers/ai-sdk-providers/google-vertex) · [Google Cloud data retention](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/zero-data-retention)
3. **OpenAI API.** It has an AI SDK adapter, and API data is excluded from model training by default. Default abuse monitoring can retain content for up to 30 days, and eligible controls depend on approval and endpoint. A provider change requires rechecking Thai answers, citations, tool behavior, and costs. [AI SDK integration](https://ai-sdk.dev/providers/ai-sdk-providers/openai) · [API data controls](https://developers.openai.com/api/docs/guides/your-data)

## Multilingual embeddings for Pinecone

1. **Pinecone Inference with `multilingual-e5-large`.** This gives the project a hosted multilingual baseline from the planned index vendor. The model accepts up to 507 tokens per input and lists a usage price of $0.08 per million tokens. Keep source passages in Supabase and store vectors, passage IDs, and scope metadata in Pinecone. [Model limits and price](https://docs.pinecone.io/models/multilingual-e5-large) · [Pinecone index options](https://docs.pinecone.io/guides/indexes/create-an-index)
2. **Gemini Embedding 2.** The Google API can embed longer inputs and PDFs, then send vectors to Pinecone. This fits the existing Gemini supplier and adds a separate embedding call and quota to the retrieval path. It is worth comparing if longer financial passages improve cited answers. [Model specifications](https://aistudio.google.com/docs/models/gemini-embedding-2) · [Gemini pricing](https://aistudio.google.com/docs/pricing#gemini-embedding-2)
3. **Self-host a multilingual model.** A model such as EmbeddingGemma gives the project control of inference and adds a serving runtime, scaling, and model maintenance. It fits if measured volume or data-handling requirements justify that work. [EmbeddingGemma model family](https://ai.google.dev/gemma/docs/embeddinggemma)

Use the same Thai and English filing passages and filters in each comparison. Check whether Thai questions retrieve English evidence, whether issuer and period filters hold, and whether the returned passages support the citations. A model change requires rebuilding the vector index. [Retrieval evaluation](../rfcs/financial-evidence-retrieval.md#evidence-needed-to-confirm-the-design)

## USD/THB rates

1. **Open Exchange Rates.** The USD-base API includes THB and publishes hourly rates on its standard offerings. It is a practical fit if the newest hourly snapshot is fresh enough for portfolio valuation. Confirm the plan and display rights for the intended deployment. [Plans](https://openexchangerates.org/signup) · [Currencies](https://docs.openexchangerates.org/reference/supported-currencies)
2. **Bank of Thailand daily interbank rate.** It provides an official Thai reference with a clear rate date. It fits if the product accepts a daily reference and falls short if it needs an intraday market rate. [Daily rate](https://www.bot.or.th/en/statistics/exchange-rate.html) · [Exchange Rates API](https://portal.api.bot.or.th/portal/catalogue-products/exchange-rates-1/0e644d4d76de4108537e1f95cf83330e/docs)
3. **Twelve Data.** It advertises real-time USD/THB rates and has plans for external data use. It moves ahead of the other options if the product requires intraday rates fresher than hourly. Verify the exact plan's freshness, quota, and display terms. [USD/THB coverage](https://twelvedata.com/currency-converter/usd/thb) · [Business plans](https://twelvedata.com/pricing-business)

Apply one timestamped rate to both cost and value in a valuation snapshot. The one-minute portfolio price refresh and the FX freshness limit are separate decisions. [Valuation requirements](../final/functional-requirements.md#fr-22-current-fx-valuation) · [FX freshness question](../requirements-questions.md#q02-thb-conversion-and-daily-profit-or-loss)

## Watchlist events

1. **EODHD for both markets, conditional on coverage.** It documents earnings and dividend calendars and lists Thai securities. Those facts alone do not establish Thai calendar completeness. Verify earnings, ex-dividend and payment dates for representative Thai and US listings, along with rights to display the data. [Calendar API](https://eodhd.com/financial-apis/calendar-upcoming-earnings-ipos-and-splits) · [Thai listings](https://eodhd.com/exchange/BK) · [Licensing](https://eodhd.com/help/commercial)
2. **SET for Thailand and Massive for the US.** SET documents corporate actions and lists a stock calendar. Massive documents US earnings through its Benzinga feed and has a separate dividends endpoint. This gives each market a dedicated source and adds two integrations and licensing checks. Verify Thai earnings schedule access separately from corporate actions. [SET corporate actions](https://www.set.or.th/app/online-data/reference-data?lang=en) · [SET calendar](https://www.set.or.th/en/market/stock-calendar/x-calendar) · [Massive earnings](https://massive.com/docs/rest/partners/benzinga/earnings) · [Massive dividends](https://massive.com/docs/rest/stocks/corporate-actions/dividends)
3. **Issuer and regulator disclosures.** This reuses filing sources for confirmed announcements and leaves more extraction work and gaps in forward-looking dates. Official Bank of Thailand and Federal Reserve calendars can supply policy meetings separately. [EDGAR API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) · [Bank of Thailand MPC](https://www.bot.or.th/en/our-roles/monetary-policy/mpc-meeting.html) · [Federal Reserve FOMC](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm)

### Macroeconomic calendar

- **Official schedules** are the closest fit for a short list of Thai and US events. Use the Bank of Thailand and Federal Reserve for policy decisions, TPSO and BLS for inflation, and NESDC and BEA for GDP. BLS offers an iCalendar feed. The Thai schedules use web pages and PDFs, which require periodic checks for changes. [Thai policy decisions](https://www.bot.or.th/en/our-roles/monetary-policy/mpc-meeting.html) · [Thai CPI](https://www.tpso.go.th/en/Page-uh9h8) · [Thai GDP](https://www.nesdc.go.th/wp-content/uploads/2026/11/Forthcoming-releases.pdf) · [US policy meetings](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm) · [US BLS calendar](https://www.bls.gov/help/hlpiCAL.htm) · [US BEA calendar](https://www.bea.gov/news/schedule/full)
- **Yahoo Finance via yfinance** is a prototype candidate. `yf.Calendars().get_economic_events_calendar()` exposes macro events. Its public signature supports date ranges and pagination. The project would need to filter the returned region field, verify Thai coverage, and confirm display rights. yfinance describes Yahoo Finance data access as intended for personal use. It would also add a Python runtime to the TypeScript stack. [Calendar API](https://ranaroussi.github.io/yfinance/reference/yfinance.calendars.html) · [Implementation](https://github.com/ranaroussi/yfinance/blob/main/yfinance/calendars.py) · [yfinance usage note](https://github.com/ranaroussi/yfinance#legal-stuff)
- **EODHD Economic Events and Trading Economics** offer country-filtered APIs. EODHD documents its macroeconomic endpoint under Fundamentals and All-in-One, with separate access from the standalone corporate calendar. Trading Economics is an alternative if we need a wider calendar or forecasts. Verify Thai event coverage and display terms before selecting either. [EODHD Economic Events](https://eodhd.com/financial-apis/economic-events-data-api) · [Trading Economics country calendar](https://docs.tradingeconomics.com/economic_calendar/country/)

### What LLMFA's Airflow DAG actually does

The reference checkout's `llmfa_airflow/dags/llmfa_dag.py` schedules a monthly run with catchup disabled. It discovers source pages and files, extracts HTML and PDFs, then uses the extraction and embedding libraries to send chunks to Pinecone. The library uses Typhoon for PDF extraction and Gemini for embeddings. The DAG uses shared local paths, clears its output directory at the start of a run, and reports some task errors as result data. Those paths do not provide durable per-document checkpoints across workers. Returning an error record also skips Airflow's automatic retry for that task unless the task fails. These are observations from the old DAG and its README. They establish a reusable sequence and candidate extraction helpers. They leave current source permissions, Thai extraction quality, retry behavior, and throughput unverified.

The LLMFA deployment config specifies `LocalExecutor` with PostgreSQL for Airflow metadata. The reference `pyproject.toml` allows Airflow 3, and the DAG and deployment still use older interfaces such as `schedule_interval` and the `webserver` command. Check compatibility with the selected version before porting. LocalExecutor runs task processes on the scheduler host, so OCR and bulk jobs can consume the same memory and worker slots as publication. Pools cap concurrent work, with overall headroom still needed for the scheduler and publication tasks. [LocalExecutor](https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/executor/local.html) · [Pools](https://airflow.apache.org/docs/apache-airflow/stable/administration-and-deployment/pools.html) · [Airflow components](https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/overview.html)

Vercel's Fair Use Guidelines list functions that query APIs as acceptable examples and list scrapers as excluded. The old DAG's domain crawl and a bounded check of a permitted source API or feed are distinct workloads. [Vercel Fair Use Guidelines](https://vercel.com/docs/limits/fair-use-guidelines)

### Phase 1 schedule feasibility

Checked on 21 November 2026. The verification covers Vercel's published limits, calendar timing, and a sample from each source path. The worker, migrations, and schedules are still pending implementation. The approved cadence is recorded in [FR-03](../final/functional-requirements.md#fr-03-daily-brief-content-and-publication) and [FR-12](../final/functional-requirements.md#fr-12-financial-data-and-news).

- **Scheduled runs.** A 31-day month with 23 weekdays has at most 1,488 news checks, 744 brief jobs, 414 US checks, and 69 Thai checks. The total of 2,715 is below Vercel Hobby's team limit of 5,000. This estimate assumes one dispatch per scheduled check or publication slot and excludes manual runs and other projects. Hobby also limits each Function to five minutes and includes 4 active CPU hours and 360 GB-hours of provisioned memory per month. Schedule counts alone cannot establish that worker and web usage fit those compute allowances. [Schedule limits](https://vercel.com/docs/schedules/limits) · [Function duration](https://vercel.com/docs/functions/configuring-functions/duration#duration-limits) · [Compute allowances](https://vercel.com/docs/functions/usage-and-pricing)
- **Timing.** The normal 15-minute dispatch window leaves about 10 minutes between the end of the `:00` news dispatch window and the start of the `:25` brief window. A news job dispatched at `09:15` Bangkok time with ten minutes of queue delay and three minutes of processing would finish at `09:28`. In that case the `09:25` brief can use a previously completed batch. This is a timing example, using documented dispatch windows and assumed queue and processing delays. A local calendar check confirmed the weekday EDGAR schedule crosses Bangkok midnight and shifts by one hour in Bangkok when Eastern time changes. [Vercel scheduling concepts](https://vercel.com/docs/schedules/concepts)
- **Source checks.** The live Federal Reserve monetary-policy RSS response had 15 releases with distinct source URLs and parseable publication timestamps. A local probe over saved EDGAR Submissions and Company Facts for AAPL, JPM, and WMT detected a new accession once and skipped it on replay. The saved PTT annual PDF had extractable text on 234 of 236 pages and Thai characters on one page. That sample leaves extraction and table accuracy on Thai-language filings unverified. Source permissions for automated Yahoo Finance news and storage or AI use of selected Thai filings remain open. [Federal Reserve feeds](https://www.federalreserve.gov/feeds/feeds.htm) · [EDGAR APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) · [PTT filing listing](https://market.sec.or.th/public/idisc/en/FinancialReport/ALL-0000001074) · [Thai SEC website policy](https://www.sec.or.th/EN/Pages/Footer/WebsitePolicy.aspx) · [Yahoo terms](https://legal.yahoo.com/sg/en/yahoo/terms/otos/index.html)

A preview run needs to measure scheduler dispatch delay, queue wait, wall time, active CPU, and time until evidence is searchable or the brief is published. Run a check with no changes, an EDGAR amendment, and a representative Thai-language interim filing. Replay a completed run to verify that it produces no duplicate versions. Delay one news batch past the brief start and verify that the brief uses the previous completed batch. Project compute usage from those runs together with web and stock-summary traffic before treating Hobby capacity as verified.
