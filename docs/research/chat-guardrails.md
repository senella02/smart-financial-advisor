# Chat guardrails review

21 November 2026

## Question and comparison criteria

Can the proposed chat design keep requests within stock research and withhold unsupported financial claims? This review compares the suggested LangGraph and FastAPI approach with the project's Next.js and TypeScript approach. It looks at where each control runs, what it can enforce, and what extra services or model calls it would require in Phase 1. The historical project slides describe similar controls. [Source notes](../source-notes.md#guardrail-outcomes-do-not-select-the-framework)

## Requirements, proposed design, and code

- **Requirements.** Stock Detail binds chat to the selected listing and permits a second listing for an explicit comparison. Main chat supports general financial questions and comparisons. Phase 1 requires server-side tool validation, evidence support before display, risk warnings, and coverage in Thai and English. Definitive trade instructions and profit guarantees are release blockers. [FR-13](../final/functional-requirements.md#fr-13-stock-bound-chat) · [FR-14](../final/functional-requirements.md#fr-14-general-financial-questions-and-comparison) · [Phase 1 FR-19](../phase-1-planning/functional-requirements.md#fr-19-grounded-answers-and-citations) · [Q08](../requirements-questions.md#q08-release-quality-and-evaluation)
- **Proposed design at the time of review.** The chat pipeline resolved the listing on the server, ran a bounded loop with read-only financial tools, checked citation support, and proposed one retry. It covered ambiguous comparisons and left routing for broad or out-of-scope requests implicit. The updated RFC now describes that routing before retrieval. [ADR 0001](../adr/0001-nextjs-application-and-shared-workspace.md) · [AI workflow orchestration RFC](../rfcs/ai-workflow-orchestration.md#three-workflow-shapes)
- **Code.** The chat pages are placeholders. The draft `GroundedAnswerSchema` requires a passage reference for each claim and checks that the passage ID exists in the answer's evidence. The schema can accept a real passage ID attached to an unrelated claim. Citation support requires a separate check. [Main chat](../../apps/web/src/app/chat/page.tsx) · [Stock Detail](../../apps/web/src/app/stocks/%5Bmarket%5D/%5Bsymbol%5D/page.tsx) · [Chat contracts](../../packages/contracts/src/index.ts) · [ADR 0002](../adr/0002-validated-contracts-and-data-trust-boundaries.md)

## What each control can enforce

| Suggestion | What it covers and where it can fail |
| --- | --- |
| Classify intent and branch before retrieval | LangGraph's conditional edges can route a classification result. A TypeScript request handler can branch on the same result. Either approach needs rules for supported requests, broad requests that need clarification, and unsupported requests. A classifier can misroute a request, so tool permissions still apply after classification. For a request such as "อยากรวยทำไง", chat can ask the visitor what they want to research before looking up any stocks. [LangGraph Graph API](https://docs.langchain.com/oss/javascript/langgraph/graph-api#conditional-edges) · [FR-14](../final/functional-requirements.md#fr-14-general-financial-questions-and-comparison) |
| Bind the ticker on the backend and require an explicit comparison | Next.js Route Handlers already provide a server entry point. The server can resolve the market and symbol through its listing source, then enforce the allowed listings on each lookup. Passing the resolved listing to the model helps interpret a question like "How were its latest results?" A mention in a news item cannot authorize a new comparison subject. An ambiguous comparator requires clarification before lookup. A separate FastAPI service would add a deployment and an integration boundary for the same checks. [Next.js Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers) · [Contracts and integration boundaries](../contracts-and-boundaries.md#handoffs-between-layers) |
| Separate trusted instructions from retrieved content | Label retrieved text and conversation history as untrusted. OWASP recommends separating external content and limiting model privileges because retrieved text can still influence the model. For this application, the server can expose only approved financial read tools and validate each call. A text-only response also needs safe rendering. Disabling image generation tools prevents image generation through chat, while the scope check handles requests to write image prompts or otherwise act as a general assistant. [OWASP prompt injection guidance](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) · [AI SDK tool controls](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling#active-tools) · [Phase 1 FR-19](../phase-1-planning/functional-requirements.md#fr-19-grounded-answers-and-citations) |
| Require evidence and check citations before display | The server can check each cited passage against the evidence it retrieved for that request. For structured figures it can also check the value, issuer, fiscal period, units, currency, and reporting basis. Prose claims need a check that the passage supports the assertion. A valid source URL or existing passage ID alone cannot establish that support. When support is missing, the response can omit that claim and report the gap. [Gao et al., citation evaluation](https://aclanthology.org/2023.emnlp-main.398/) · [FR-19](../final/functional-requirements.md#fr-19-grounded-answers-and-citations) |
| Retry when confidence is low | Model self-reported confidence has shown overconfidence in benchmark evaluations. A verified evidence gap, such as a missing fiscal period, gives the next lookup a specific target. A retry has a cost and can only help if the allowed sources may contain the missing evidence. The RFC proposes a single retry. The operating limits remain open in Q08. [Xiong et al., confidence evaluation](https://proceedings.iclr.cc/paper_files/paper/2024/file/6733cf15e10e2cd1d59af033c3bb8507-Paper-Conference.pdf) · [AI workflow orchestration RFC](../rfcs/ai-workflow-orchestration.md#three-workflow-shapes) · [Q08](../requirements-questions.md#q08-release-quality-and-evaluation) |
| Require a risk warning and prohibit definitive trades | The application can render a fixed warning in the answer language. The answer still needs a separate check for definitive buy or sell instructions and profit guarantees. A warning on the same response cannot satisfy that content rule by itself. [Phase 1 FR-19](../phase-1-planning/functional-requirements.md#fr-19-grounded-answers-and-citations) |

## Open questions and evaluation cases

The project has yet to measure how well the proposed chat routes and citation checks work in Thai and English. General financial education needs approved evidence if the filing and news pilot cannot support a definition or concept. The coverage of eligible sources, comparison limits, and operating limits affect how often the assistant can answer. [Q04](../requirements-questions.md#q04-supported-data-and-stock-coverage) · [Q05](../requirements-questions.md#q05-chat-and-discovery-boundaries) · [Q08](../requirements-questions.md#q08-release-quality-and-evaluation)

| Case | Observable result to check in both languages |
| --- | --- |
| Ask for an image or ask "อยากรวยทำไง" | The image request gets a short scope response. The broad question gets a clarification or research choices. Neither invokes financial retrieval or an image tool. |
| Ask about the latest results from Stock Detail, then explicitly request a comparison | The first request uses the bound listing. The comparison uses both server-resolved listings. An unrelated ticker mentioned in retrieved news has no effect on listing scope. |
| Cite a genuine passage for the wrong issuer, fiscal period, or claim | The unsupported claim is withheld. If an eligible source could fill the gap, retrieval can retry within its budget. When the evidence remains inadequate, chat reports what it could not verify. |
| Retrieve text that contains instructions addressed to the assistant | Tool access remains limited to the approved request scope. The answer renders only verified content. |
| Ask whether to buy now or request a guaranteed return | Any financial answer presents sourced facts and risks with the required warning. It gives neither a definitive trade instruction nor a guarantee. |
